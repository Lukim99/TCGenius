# [일일]지혜의 보석

웹 **콘텐츠 → 게시판**에서 오늘의 퍼즐을 풀고 **보상 받기**를 누르면 지혜의 보석을 받는다. 신규 등록 시 보상은 1개, 참여 레벨은 1~300이다. 이후 보상과 활성 여부는 운영 `rpgenius_data.Quest`의 관리자 설정을 그대로 사용한다.

## 자동 출제

- 한국시간 **2026-09-15 00:00부터 60종**을 아래 순서대로 하루에 하나씩 순환한다. 60일 동안 유형이 겹치지 않는다. 숫자나 이름만 바꾼 변형을 별도 유형으로 세지 않는다.
- 2026-09-14까지 발행한 기존 4종의 문제·정답·ID는 그대로 유지한다. 운영 서버에는 확장 코드 배포와 재시작이 필요하며, Quest 재등록이나 DB 수정은 필요 없다.
- 날짜·계정 ID·퀘스트 ID로 문제를 결정한다. 새로고침하거나 서버를 재시작해도 같은 날의 문제는 유지된다.
- 추론·배치 문제는 가능한 답을 계산하고, 답이 하나가 되도록 단서나 고정 칸을 남긴다. 최적화 문제는 최솟값·최댓값을 계산하며, 여러 최적 경로 중 하나를 입력해야 하는 문제에는 사전순 등 동점 처리 규칙을 명시한다.
- 문제 도표와 답안 격자를 구분해 표시한다. 숫자·문자·반복 비트·연산자·기약분수·이동 경로를 각각 해당 규칙에 맞춰 입력할 수 있다. 고정된 `0`은 빈칸과 구분된다.
- 외부 AI/API, 예약 작업, 문제 파일의 수동 추가가 필요 없다. 날짜가 바뀐 후 첫 조회에서 새 문제를 생성한다.
- 오답 횟수 제한은 없고 제출 간격은 5초다. 정답과 생성용 시드는 클라이언트에 보내지 않는다. 레벨 스킵이나 일반 게임 이벤트로 달성할 수 없다.

## 기존 시스템과 연결

목표 타입 `wisdomPuzzle`은 매일 갱신되는 퍼즐 1회 해결을 뜻한다. `user.quests[id]`에 당일 정답 여부·시도 횟수와 기존 보상 수령 기록을 함께 보관한다. 답안 제출과 수령은 기존 계정별 명령 큐에서 처리하며, 보상과 수령 기록을 같은 유저 저장에 포함한다. 저장 실패 시 성공 응답을 보내지 않고 재시도하며, 수령 결과를 재사용해 중복 지급을 막는다. 전날 화면에서 보낸 답안이나 수령 요청은 거부한다.

`wisdom_puzzle.js`는 날짜로 `wisdom-v1`과 `wisdom-v2`를 선택한다. 기존 4종의 생성 규칙은 유지하고 56종은 `wisdom_puzzles/`에 추가했다. 향후 생성 규칙이나 순환 순서를 변경할 때도 이미 발행한 당일 문제를 유지하도록 버전을 구분해야 한다.

## 최초 등록

새 코드를 배포할 때 한 번만 실행한다. 먼저 등록할 내용을 조회한다.

```powershell
node scripts/init_wisdom_quest.js
```

확인한 신규 퀘스트를 등록하고 새 코드의 서버를 시작한다. 서버는 시작할 때 운영 Quest 목록을 읽는다.

```powershell
node scripts/init_wisdom_quest.js --apply
```

이 명령은 운영 Item 목록에서 지혜의 보석을 찾아 연결하고, 이름이 같은 퀘스트가 없을 때만 새 ID로 추가한다. 기존 퀘스트·아이템·보상·비활성 설정·빈 구성은 변경하지 않는다. 등록 직전 Quest와 Item의 동시 변경도 검사한다. 서버 시작이나 모듈 import에서는 등록하지 않는다.

## 검증

```powershell
node --test tests/wisdom_puzzle.test.js tests/wisdom_variety.test.js tests/wisdom_quest.test.js tests/quest_skip_min_level.test.js
```

운영 자격 증명을 읽지 않고 저장소 경계를 격리한다. 기존 730개 문제의 정답 유일성과 발행 ID 보존, 60종 × 두 순환 × 10계정의 1,200개 생성·채점, 도표·단서·최적화 결과를 검사한다. 60종 전부를 실제 Express 게시판·제출·수령 경로로 검증하고, 확장일과 일일 자정 경계, 동시 요청, 저장 실패, 운영 보상 설정 보존도 검사한다.
