# 닉네임 색깔 변경권 적용

기존 전직 프레스티지 권한인 `jobPrestige`를 유지한다. 계정 공용 권한과 골드 획득량 +5%는 그대로이며, `nicknameColor`만 캐릭터 레코드에 저장한다. 기존 사용자 레코드는 일괄 변경하지 않는다. 기본 색상은 기존 표시를 따른다.

운영 `Item` 카탈로그의 `use: 전직프레스티지` 아이템(2026-11-24 조회 시 178번) 이름과 설명만 변경한다. 번호, 수량, 거래 설정, 사용 코드, 상점 가격 및 꾸러미 연결은 유지한다. 아이콘도 기존 자산을 사용한다. 일반 프레스티지 프레임은 유지하고 전직 프레스티지 프레임만 제거한다.

운영 배포 시 점검 상태에서 이전 서버의 저장을 마치고 중지한 뒤 아래 명령을 명시적으로 실행한다. 실행 후 새 서버를 시작해 변경된 카탈로그를 읽게 한다. 부팅과 테스트에서는 실행하지 않는다.

```sh
node scripts/rename_nickname_color_ticket.js
node scripts/rename_nickname_color_ticket.js --apply --backup-dir=/var/lib/rpgenius/maintenance-backups/nickname-color-ticket
```

로컬 읽기 전용 확인에는 `--env-dir`을 사용할 수 있다. `--apply`는 변경 전 아이템 전체가 조회 당시 값과 같을 때만 이름과 설명 두 필드를 갱신한다. 이미 새 이름이면 운영자의 후속 설명 변경도 그대로 둔다. 원본 백업 파일을 덮어쓰지 않는다.

색상 목록은 인증된 사용자에게만 제공하며 서버 사용자 캐시에서 생성한다. 브라우저는 화면이 보일 때 최대 분당 한 번 갱신하고, 본인이 변경한 색은 즉시 반영한다. 색을 고르는 동안에는 DB 저장을 하지 않는다. 적용 버튼을 누르면 색 필드만 변경하며, 대기 중인 사냥 저장은 기존 저장소의 규칙에 따라 함께 확정될 수 있다.

검증: 관련 격리 테스트 67개 통과. PC, 모바일 세로/가로 화면, 색상 저장 후 새로고침, 프로필, 랭킹, 전투 HUD 표시를 브라우저에서 확인했다. 별도 실행한 `tests/unique_avatar.test.js`의 HTTP 테스트는 기존 모의 DB가 계정 분리 트랜잭션을 지원하지 않아 실패했다. 이번 프레임 변경은 지원되는 격리 저장소에서 실제 프로필 API와 이미지 합성 테스트로 검증했다.
