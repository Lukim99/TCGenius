# 캐릭터별 레이드 보상 기록 이전

최초 클리어 보상과 주간 보상 횟수는 `raidRewardProgress`에 캐릭터별로 저장한다.

- 흑화 호두 일반/익스트림은 캐릭터당 주 3회 통합 제한을 유지한다.
- 부타게임 일반/하드, 대저택 일반/하드는 각각 캐릭터당 주 1회 통합 제한을 유지한다.
- 흑화 호두 익스트림과 대저택 나이트메어의 최초 보상은 캐릭터당 1회다.
- 기존 계정 기록은 `characterNumber: 1`인 캐릭터만 이어받고, 기존 부캐는 빈 기록으로 시작한다. 화면 순서나 현재 접속 캐릭터로 판단하지 않는다.
- 칭호와 칭호 누적 진행도는 계정 공용이다. 생일 이벤트 보상 기준은 이번 변경 대상이 아니다.

## 운영 적용

서버 시작이나 배포 스크립트에서 자동 실행하지 않는다. 새 코드가 운영 요청을 받기 전에 명시적으로 이전해야 한다.

1. 먼저 쓰기 없는 사전 확인을 실행한다.

   ```powershell
   node scripts/migrate_raid_reward_progress.js --env-dir=C:/Users/dodom/Downloads/tcgenius
   ```

2. 운영 적용 시 점검 모드를 켜고 진행 중 요청과 지연 저장을 마친 뒤 기존 서버를 중지한다. 실행 중인 서버의 캐시에 옛 데이터가 남은 상태에서 이전하지 않는다.
3. 새 코드와 의존성이 있는 환경에서 같은 스크립트를 `--apply`로 실행한다. 서버에서 환경 변수를 제공하면 `--env-dir`는 생략한다.
4. 출력된 백업 경로를 보관한다. 각 계정의 기존 기록과 캐릭터 소속이 그대로일 때에만 해당 계정의 이전을 한 트랜잭션으로 반영하며, 반영 후 다시 읽어 검증한다. 실패하면 원인을 확인하고 재실행한다. 이미 이전된 기록은 덮어쓰지 않는다.
5. 새 코드를 시작하고 준비 상태를 확인한 다음 점검 모드를 해제한다. 이전 전 버전과 새 버전을 동시에 실행하지 않는다.

공유 칭호와 원래 계정 기록은 보존되며 새 레이드 보상 판정에서는 더 이상 공유 기록을 사용하지 않는다. 새로 생성하는 캐릭터와 아직 계정 분리 전인 기존 사용자는 생성/계정 분리 절차에서 새 필드를 저장한다. 이미 분리된 캐릭터에 필드가 누락됐으면 보상 지급을 막아 중복 지급을 방지한다.
