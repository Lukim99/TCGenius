# 포인트 사용 기록과 관리자 통계

관리자 → 로그 → **포인트 사용 통계**에서 기간(KST), 사용처, 구분, 닉네임·상품명·계정 ID로 조회한다. 날짜별·사용처별·상품/행동별 합계와 50건 단위 상세 목록을 제공한다. 합계는 전체 조회 결과로 계산하므로 상세 페이지 수나 Supabase의 기본 조회 건수 제한에 영향을 받지 않는다.

기록 당시 관리자였거나 현재 관리자인 계정은 모든 통계와 상세 목록에서 제외한다. 감사 기록 자체는 보존하며 관리자 포함 옵션은 제공하지 않는다. 기록 도입 전 사용 내역은 소급 생성하지 않는다.

## 기록 범위

| 사용처 | 기록 내용 |
| --- | --- |
| 포인트를 사용하는 모든 상점 | 상품 ID·이름, 구매 횟수, 단가, 지급 수량, 상점 구분 |
| 퍼스널뽑기 | 한 칸 뽑기·흔들기·새로고침, 요청 ID, 판 번호, 선택 위치, 공개된 결과·보너스; 무료 새로고침도 0P로 기록 |
| 축복 | 축복 종류, 기간, 만료 시각 |
| 메일 포인트 선물 | 수신자, 메일 ID; 소비와 분리 |
| 관리자 회수·충전 취소 | 수행 관리자, 충전 로그 ID 등; 소비와 분리 |
| 그 밖의 저장 시 포인트 감소 | 미분류 차감으로 기록하여 누락을 확인할 수 있게 함 |

공통 필드에는 거래 UUID, 시각, 계정, 당시 닉네임·관리자 여부, 차감액, 차감 전후 잔액, 웹/게임 경로가 포함된다. 퍼스널뽑기의 아직 열리지 않은 보상판은 기록하지 않는다.

현재 운영 코드의 프리셋 해금은 가넷을 소비하므로 포인트 원장에는 포함하지 않는다.

## 저장과 재전송

영구 원장과 집계 함수는 Supabase의 `public.rpgenius_point_usage`, `public.rpgenius_point_usage_report`다. 변경 스키마는 `supabase/migrations/20261109031749_rpgenius_point_usage.sql`에 있다. 서버 시작이나 import에서 스키마·운영 콘텐츠를 자동 생성하지 않는다.

기존 포인트 잔액이 DynamoDB에 있으므로, 잔액 차감과 미전송 기록(`pointUsageOutbox`)을 같은 지갑 저장/트랜잭션으로 확정한다. 확정된 기록만 Supabase로 전송하고 성공하면 임시 기록을 지운다. Supabase 장애나 재시작 후에는 기존 유저 캐시 스윕에서 재전송한다. 거래 UUID의 중복 삽입을 무시하여 같은 기록이 두 번 집계되지 않는다. 관리자 화면에 전송 대기 건수를 표시한다.

장기 전송 장애로 한 계정의 임시 기록이 128 KiB를 넘으면 새 차감을 저장하지 않고 재시도 안내를 반환한다. 배포 전에 서버용 키와 연결을 확인해야 한다.

## 환경변수와 접근 권한

- `SUPABASE_URL`: 위 원장이 생성된 프로젝트 URL.
- `SUPABASE_SECRET_KEY`: **같은 프로젝트의 서버용 secret 또는 legacy service_role 키**. 포인트 기록은 이 값을 우선 사용한다. 없을 때만 `SUPABASE_KEY`를 사용하며, 공개용 publishable/anon 키는 사용할 수 없다.
- 키를 브라우저 코드·응답·로그에 노출하지 않는다. 다른 프로젝트용 `_P` 환경변수로 대체하지 않는다.
- 테이블에는 RLS가 활성화되어 있고 공개 접근 정책은 없다. `anon`/`authenticated`는 조회·삽입·집계 함수 실행 권한이 없다. `service_role`에만 원장 조회·삽입과 집계 함수 실행 권한을 준다.
- HTTP 통계 API는 기존 관리자 인증을 통과해야 하며 서버가 현재 관리자 ID 목록을 집계 함수에 전달한다.

운영 적용은 해당 Supabase 프로젝트에 마이그레이션을 적용하고 서버 환경변수를 설정한 뒤 애플리케이션 코드를 배포/재시작한다. 운영 데이터로 시험 구매나 가짜 원장 삽입을 하지 않는다.
