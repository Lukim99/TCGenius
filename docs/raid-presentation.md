# 레이드 공통 패턴 표시와 관문 전환

잉여왕, 흑화 호두, E세계대저택은 `partyquest.js`의 전투 엔진과 `public/party.js`의 전투 화면을 공유한다. 새 레이드도 아래 규칙을 사용한다. 보상, 피해량, 패턴 발동 조건, 해금 조건은 이 연출 계층에서 변경하지 않는다.

## 전투 계산

타격의 수치 판정은 필드, 훈련장, 월드보스와 PVP에서 사용하는 `rpgenius.calculateAttackHitResult()`를 호출한다. 레이드의 `calculateOutgoingDamage()`는 역할 보정, 전투 중 버프와 대상 디버프를 준비하고 공통 함수의 결과를 기존 레이드 이벤트 형식으로 변환한다.

- 치명타, 방어력과 관통력, 연격, 속성, 고정 피해, 추가 피해, 타격별 반올림을 레이드에 별도 구현하지 않는다. 몬스터의 연격, 치명타, 방어 계산과 피해 변동도 `rpgenius`의 공통 함수를 사용한다.
- 장비의 타격 전후 처리는 공통 계산기의 `beforeAttackUnit`과 `afterAttackUnit`에 연결한다. 고정 다단 공격은 하나의 공격으로, 연격은 타격마다 별도의 공격으로 장비를 처리한다. `separateBasicAttackHits`를 지정한 일반 공격 스킬은 실제 타격 수로 공격 횟수를 센다.
- 잡몹 단계는 `room.mobMonster`에 대상 상태를 유지한다. 기본 공격, 스킬, 소환수와 장비 효과는 `getPhaseCombatMonster()`로 같은 대상을 가져온다. 공격마다 임시 몬스터를 만들면 화상과 방어 감소가 사라지므로 사용하지 않는다.
- 화상, 겁화와 유서새김은 잡몹, 엘리트와 보스 모두 `stepMonsterDebuffs()`에서 진행한다. 타격은 공통 피해 계산을 거치고 처치 수, 피해 통계와 로그에 반영한다. 화상과 겁화는 화속성이며 치명타가 발생하지 않는다. 이미 계산한 그림자 공격은 `precalculatedDamage`로 재계산을 막는다.
- 지속 피해와 소환 공격은 장비 발동, 공격 횟수, 공격 시 회복이나 다음 직접 공격의 버프를 소모하지 않는다. 관문 전환과 전투 종료에서는 이전 대상 상태를 정리하고, 지속 피해로 관문이 끝나면 해당 틱도 중단한다.
- 레이드의 역할, 패턴, 보호막과 관문 규칙은 서버의 레이드 계층에서 처리한다. 실제 피해를 적용할 때 기존 보스 기믹 판정을 거친다.

`tests/mansion_raid.test.js`는 같은 스탯과 난수로 일반 몬스터, 엘리트와 보스의 공통 계산 결과를 비교하고 잡몹의 화상, 유서새김, 보스의 화속성 지속 피해와 관문 상태 정리를 검증한다. 장비 효과를 추가할 때 이 경로에서도 유지와 만료, 간접 공격의 재발동 여부를 확인한다.

## 패턴 HUD

보스 스테이지 아래 `#pqMansionRoot`와 `MansionRaidUI.update()`를 공통 HUD로 사용한다. 파일명은 기존 대저택 구현을 유지하지만, `public/mansion-raid.js`와 `public/mansion-raid.css`가 모든 레이드의 패턴 카드, 대상 강조, 타이머를 담당한다.

- 카드에는 패턴 이름, 기존에 공개된 공식 문구, 대상 또는 참여 상태, 남은 시간만 표시한다. 새로운 대응법, 성공 범위, 추천 행동을 임의로 덧붙이지 않는다.
- 타이머는 오른쪽에 0.1초 단위로 표시한다. 진행선과 종료 직전의 색 변화도 같은 컴포넌트가 처리한다.
- 나에게 지정된 패턴은 같은 금색 배지와 대상 표시로 강조한다. 색만으로 대상을 구분하지 않는다.
- 같은 사건은 같은 `id`를 유지한다. SSE 갱신은 카드 내용만 변경하고, 클릭 중인 버튼과 초점을 다시 만들지 않는다. 새 시전에는 새 `id`를 부여한다.
- 종료된 사건은 서버 목록에서 제거한다. 상시 표식은 `remain: null`로 보내며, 제한 시간이나 마감 표시를 만들지 않는다.
- 보스 체력바 아래의 `nextPattern` 문구를 다시 표시하지 않는다. 패턴 이름과 시간이 두 곳에 중복해서 나오지 않게 한다.
- 전투 무대의 크기는 패턴 유무에 따라 바뀌지 않는다. `public/raid-presentation.css`의 고정 격자에서 입력 패널을 무대 위에 겹쳐 놓는다. 넓은 화면은 오른쪽 패널, 세로 모바일은 무대 하단 패널, 낮은 가로 화면은 왼쪽 무대와 오른쪽 파티 및 조작부를 사용한다. 패널 때문에 보스를 옮기거나 배경과 다른 비율로 축소하지 않는다.
- 파티 카드와 공격, 스킬, 지원군, 휴대 물약은 별도 행에 유지한다. 패턴이 뜰 때 파티 높이를 바꾸거나 무대를 축소하지 않는다. 휴대 물약은 아이템 이미지, 수량, 키와 원형 쿨타임으로 표시한다.
- 지원군은 공격과 개인 스킬 위의 독립된 줄에 표시한다. 이미지와 이름이 모두 들어가는 버튼 높이를 확보하고 이미지의 flex 축소를 막는다. 지원군 버튼을 좁은 개인 스킬 영역에 끼워 넣거나 이미지 높이를 줄여 찌그러뜨리지 않는다.
- 받아쓰기의 입력칸과 버튼을 flex 축소로 잘라내지 않는다. 입력 패널 안에서만 스크롤하며 키는 하단에 고정한다. 작은 화면에서도 키 높이는 최소 44px이다. 스냅샷 갱신으로 입력 중인 패널의 스크롤과 초점을 초기화하지 않는다.
- 모바일과 낮은 가로 화면에는 무대 밖 상단에 채팅 열기 버튼을 둔다. 패턴 카드나 보스 말풍선이 표시되어도 이 버튼은 사용할 수 있다. 펼친 채팅은 입력 카드보다 위에 표시하며, 접힌 채팅과 개인 HP/MP 창은 패턴을 가리지 않도록 숨긴다.
- 타부자고의 외침은 `presentation: 'speech'`와 `message`로 전달한다. "야, 김쁠뿡!!!!!!" 말풍선만 표시하고 패턴 카드, 대응법과 토스트는 추가하지 않는다. 서로 다른 생존자의 응답이 기존 필요 인원에 도달하면 서버가 즉시 한 번만 성공을 판정한다. 말풍선은 "으악!"으로 바뀌고 기존 8초 그로기가 시작된다. 다른 채팅 기믹의 마감 판정은 유지한다. 말풍선 꼬리는 원본 보스의 입 좌표를 같은 `cover` 변환으로 따라가며, 작은 무대에서는 체력바 아래에 표시한다.

일반 보스의 공개 신호는 `serializeBossPatternEvents()`에서 `monster.patternEvents`로 직렬화한다. 대저택은 기존 `monster.mansion.events`와 입력 기믹을 유지한다. 두 경우 모두 `updateRaidPatterns()`를 거쳐 같은 HUD에 도달한다.

```js
{
  id: 'cast:flame:3', // 이 사건 동안 유지되는 식별자
  kind: 'raidCue',
  effect: 'flame',   // 공개 신호에 연결할 시각 효과
  label: '화염 폭발',
  tag: '시전',
  remain: 2.4,       // 초. 상시 표식은 null
  duration: 3,
  targets: [],       // 이미 공개된 지정 대상만 포함
  responded: [],
  requiresResponse: false
}
```

사용자 입력이 필요한 새로운 기믹은 `KINDS`에 입력 패널을 추가하고, 기존 `act()`의 중복 요청 방지와 카드 갱신 방식을 사용한다. 피해 판정과 성공 조건은 서버 보스 핸들러에 둔다. `onFinish` 같은 함수나 서버 내부 상태를 공개 데이터에 포함하지 않는다.

## 전투 이미지와 패턴 효과

`serializeMonster()`는 보스의 투명 이미지 `image`, 별도 전투 배경 `background`, 분리 이미지 여부 `sprite`, 원본 구도 `scene`을 제공한다. 기존 보스의 원본은 유지하고 `RAID_ARTWORK`에서 해당 보스의 전경과 같은 장면의 배경을 함께 연결한다. 퀘스트 ID로 다른 관문의 배경을 추측해 연결하지 않는다. 파일과 생성 조건, 외부 음원 출처는 [에셋 기록](raid-assets.md)을 따른다.

- 기존 보스는 전경의 전체 캔버스 크기와 보스 위치를 원본과 같게 유지한다. `.pq-scene-plane`에 배경과 전경을 겹치고 같은 `cover` 변환을 적용한다. 따라서 화면 비율이 달라도 보스의 발과 배경 받침대가 함께 움직인다. 임의의 보스 이동, 별도 축소와 대기 애니메이션으로 이 구도를 깨지 않는다.
- `scene.aspect`는 원본 가로/세로 비율이다. `scene.subject`는 실제 보스 영역의 `[x, y, width, height]` 비율로, 알파 마스크와 효과 기준점을 정한다. 전체 전경을 기준으로 피부 효과를 계산하면 무대 전체에 번지므로 전경 영역과 실제 보스 영역을 구분한다. 흑화 호두는 `scene.alignY: 0`으로 장면 전체의 위쪽을 맞춰 체력 표시가 눈을 가리지 않게 한다. 배경과 전경에 같은 정렬을 적용한다.
- 신규 독립 스프라이트는 `framed: false`와 배경 안의 배치 좌표를 등록한다. 원본 장면이 있는 보스에 이 방식을 적용하지 않는다. 체력 표시가 얼굴을 가리지 않고 발이 바닥에 놓이는지 실제 화면에서 확인한다.
- 흑화 호두의 잡몹 단계는 `어둠 정화`로 표시한다. 전투 대상과 피해, 처치 목표의 계산은 유지하며 `sharedKillCount / killTarget`을 정화율로 표시한다. `phaseArtwork`의 전용 안뜰에 연기 장막을 그려 진행률에 따라 중앙부터 걷어내고, 다음 관문에서는 같은 안뜰에 부하가 등장한다. 재접속할 때 정화율을 0부터 다시 재생하지 않는다.

`public/raid-pattern-fx.js`의 `RaidPatternFX`는 서버가 공개한 사건을 Canvas로 그린다. 보스 이미지 위의 효과는 알파 마스크를 사용해 피부에만 적용하며, HP와 입력 HUD를 덮지 않는다.

- 단단해지기의 청동 광택, 입체 파편의 낙하와 바닥 충돌, 스피커에서 시작하는 공명의 충전과 폭발, 되울림의 두 번 파동, 벽의 진동과 잔향 파열은 효과만 표시한다. 모든 패턴을 같은 원형 빛으로 표현하지 않는다. 같은 문구를 카드로 반복하지 않으며 공식 문구는 전투 로그와 접근성 안내에 유지한다. Canvas를 사용할 수 없으면 기존 카드로 표시한다.
- 기둥, 작품 진행, 조의 의지, 축복, 받아쓰기, 맥동, 역전과 보호막은 입력 카드와 전조 효과를 함께 사용한다. 지정 대상은 파티 카드에서도 표시한다. 모이는 기운과 흩어지는 기운을 그리되 정답이나 행동 지시를 새로 추가하지 않는다.
- 작품 진행률은 서버 기준으로 100ms마다 0.1%p 감소하고 0에서 멈춘다. 공격과 완성 판정 직전에도 같은 감소량을 반영한다. 공격 때 감소 주기를 다시 시작하지 않는다. `decayNextAt`과 서버 시각 보정으로 카드와 세공 화면을 갱신한다. `carveHits`는 실제 석재 피해 또는 히든 지원군 사용에만 증가해, 시간 경과와 반복 스냅샷이 타격을 만들지 않게 한다. 성공 범위는 숨기고 공대장의 완성 버튼은 항상 활성화한다.
- 석재 세공은 원석, 머리 윤곽, 다리 틈, 전체 윤곽, 다듬은 석상, 청동의 여섯 단계 이미지를 같은 발 위치와 배율로 등록한다. 다음 외곽까지 거리와 절삭 면을 따라 재료를 덜어 내고 남는 표면은 이어서 다듬는다. 무작위 먼지나 이미지의 단순 노출로 대신하지 않는다. 아틀라스 준비는 유휴 시간에 나눠 수행하고, 공격에는 실제 석재 질감의 파편과 외부 타격음을 연결한다. 재접속은 현재 형태에서 시작하며 종료 때는 외피가 떨어져 원래 청동상으로 이어진다.
- 위플래쉬의 잔향 전환은 서버의 4초를 따른다. 우퍼가 수축하고 램프가 꺼진 뒤 0.55초부터 실제 외장에 금이 퍼진다. 2.1초부터 잠시 빛이 가라앉고, 2.65초에 외장 판이 두께를 보이며 떨어진다. 틈 뒤에 이미 있던 잔향이 드러나며 2.95초부터 어깨를 기준으로 팔을 뻗는다. 3.7초부터 등록 원본으로 연결하고 실제 무대의 디코딩이 끝날 때까지 마지막 장면을 유지한다. 보스와 배경의 등록 좌표를 공통으로 사용하고 동작 줄이기에서는 파편 이동과 팔 동작을 생략한다.
- 다른 레이드의 보호막, 반사, 저주, 주시와 시전도 같은 효과 계층에 연결한다. 신호가 없는 즉시 공격에 임의의 시전 시간이나 대응 기회를 만들지 않는다.
- 효과는 패턴의 성격에 맞춘다. 흑화 증폭은 몸으로 응축되는 먹빛 연기와 낮은 진홍색 맥동, 재생은 몸의 결에 스며드는 회복광으로 구분한다. 화염은 질감 있는 화염의 예열, 분출, 연기와 중력에 따라 떨어지는 잔불로 이어진다. 기 모으기는 몸으로 흡수되는 기운, 대포는 위에서 내려오는 궤적으로 표현한다. 칠흑의 방패는 몸 표면에 닫히는 검은 반사막, 모찌 보호막은 탄성 있는 막, 레인 보호막은 물의 장막으로 구분한다.
- 입체 파편과 같은 재질, 원근과 무게를 기준으로 한다. 화염과 퍼즐은 외부 애니메이션 또는 알파 텍스처를 사용하고, 몸의 빛은 보스 알파 안에서 광원 방향에 맞춰 합성한다. 균일하게 나열한 불꽃 도형, 꽃잎, 회복 보석, 꺾쇠, 조준 기호, 장식 고리와 하중 막대를 효과로 쓰지 않는다. 튀어오르기와 조의 의지는 실제 파편과 먼지의 낙하로 표현한다. 얼굴, HP와 입력 영역을 가리지 않으며 원본 보스와 배경의 위치를 움직이지 않는다.
- 화염은 25프레임 시트의 불꽃 흐름을 재생한다. 바닥의 기준점은 고정하고 불마다 점화 시각, 깊이, 크기와 프레임을 다르게 한다. 질감 한 장을 반복 확대하거나 기울여 통통 튀게 만들지 않는다. 분출은 한 번만 커져 위로 말려 오르고, 아랫몸의 조명과 뒤늦게 상승하는 연기가 이어진다. 시트의 검은 바탕은 처음 사용할 때 광량 알파로 바꾸고 캐시해 투명 효과 캔버스에 검은 사각형이 남지 않게 한다.
- 회복은 작은 비취색과 금빛 입자가 옆구리와 아랫몸 주변에서 곡선을 따라 여러 지점으로 모여 흡수되는 흐름을 사용한다. 일부 입자는 보스 뒤에 가리고, 도착한 자리에는 보스 알파 안에서만 짧은 회복광을 남긴다. 긴 세로 기운, 솟아오르는 가시, 수평 주사선이나 얼굴 전체를 덮는 섬광으로 대신하지 않는다. 동작 줄이기에서는 이동 없이 도착 지점의 빛만 천천히 표시한다.
- `cueBossEffect()`는 재생, 어둠 폭발, 치명 반사, 부활, 퍼즐, 딜링과 튀어오르기의 실제 발동을 짧은 시각 사건으로 보낸다. 재생은 HP가 실제로 증가했을 때만 발생하며 `amount`는 실제 회복량이다. 사건의 식별자는 발동마다 새로 만들고 같은 스냅샷에서는 유지한다. 이 사건에 시전 시간이나 입력 카드를 추가하지 않는다.
- 타부자고의 확실한 딜링은 마지막 누적 단계의 남은 타이머가 3초 이하일 때 `dealing-ready` 전조를 보낸다. 실제 무기 표면에 열기가 올라가고 몸의 기운이 창끝으로 모이며 실제 타격으로 이어진다. 사건 ID는 누적 주기 동안 유지하고 남은 시간은 서버 타이머를 따른다. 기믹, 반사, 보호막과 그로기로 공격이 멈추면 전조도 멈춘다. 기존 공격 시점과 피해량을 바꾸지 않으며 예고 토스트를 표시하지 않는다.
- 사건 ID, 방의 시작 시각과 관문, 보스 형태로 재생을 구분한다. 반복 SSE, 재접속과 지나간 신호 때문에 소리를 처음부터 재생하지 않는다. 서버가 제거한 패턴은 효과도 종료한다. 완료된 타격의 잔상은 짧게 끝내며, 화염은 1.5초 안에 연기와 잔불까지 가라앉힌다. 관문 전환과 탈퇴는 이 잔상도 즉시 정리한다.
- 시전 끝의 타격은 서버의 `stage: 'resolved'` 신호로 이어서 그린다. 이 신호는 같은 사건 ID와 끝난 시점의 `remain`을 사용하고 입력 카드는 숨긴다. 마지막 순간에 기절로 중단되더라도 완료 신호가 없으면 폭발, 착탄과 처형 효과음을 재생하지 않는다. 치명 반사는 현재 효과가 끝날 때까지 새 효과를 겹쳐 만들지 않는다.
- 공명은 외부 신호음 세 번과 폭발음, 되울림은 외부 신호음 두 번씩을 재생한다. 회복, 화염, 보호막, 흑화와 패턴 타격에는 [에셋 기록](raid-assets.md)의 외부 RPG 음원을 각각 연결한다. 서로 다른 재질의 패턴에 공통 충전음을 반복 배정하거나 브라우저 기본 합성음을 추가하지 않는다. 카운트다운, 일반 타격, 치명타, 스킬, 물약과 전투 시작은 기존 효과음을 유지하고, 클리어와 실패에는 새 종료 음원을 사용한다. 기존 효과음 볼륨 설정에 연결한다.
- 관문 컷씬, 전멸, 결과, 방 이동과 숨겨진 탭에서는 진행 중인 효과음과 프레임을 정리한다. 동작 줄이기 설정에서는 빠른 이동 대신 고정 신호를 표시한다.
- 전투 격자의 `display`는 활성 화면에만 적용한다. 탈퇴하면 로비로 전환하고 패턴, 선택, 투표와 대상 선택 UI를 정리한다. 준비 및 전투의 파티 카드 성급은 기존 카드 표기인 `1성`부터 `9성`, `𝛧`, `𝛴`, `𝛀`를 사용한다.

## 스킬 선택과 설정

스킬 선택과 설정은 월드보스 선택 카드와 훈련장 설정 패널에 맞춘 금속 프레임과 금색 강조를 사용한다. `.pq-raid-dialog`로 공통 틀을 유지한다.

- 스킬 카드는 서버 정의의 이름, MP, 재사용 시간 또는 패시브 구분, 설명을 표시한다. 실제 선택 버튼으로 확정하고 요청 중에는 중복 선택을 막는다. 같은 선택지가 다시 전달되면 기존 카드, 초점과 스크롤을 유지한다. 넓은 화면에서는 세 장을 나란히, 좁은 화면에서는 세로 목록으로 표시하고 본문 안에서만 스크롤한다.
- 설정은 사운드와 단축키 탭을 사용한다. 제목, 탭과 하단 버튼은 고정하고 본문만 스크롤한다. 볼륨과 단축키의 기존 저장 기능을 유지한다. 다른 탭으로 이동하거나 닫으면 단축키 입력 대기를 취소한다.

## 지원군과 파티원 전투 효과

`public/raid-party-fx.js`의 `RaidPartyFX`는 `party-effect` SSE로 실제 피해, 회복과 보호막 판정을 받는다. 체력 스냅샷의 차이로 추측하지 않는다. 같은 순간의 피해와 회복, 체력 손실 없는 보호막 방어도 각각 표시한다. 피해량, 회복량, 보호막 지속시간, 적용 제한과 전투 통계 계산은 기존 엔진이 결정한다.

- 사건은 `id`, `roomId`, `startedAt`, `phaseIndex`, `at`, `kind`, `source`, `target`, `amount`를 전달한다. 지원군은 `support`와 기존 `icon`을 함께 보낸다. 함수, 비공개 스킬 선택이나 계정 데이터는 포함하지 않는다.
- 지원군은 유효한 공대장 호출에만 한 번 등장한다. 지오는 묵직한 대지 타격, X는 교차 참격과 쿨타임 해제, 피카츄는 금빛 방전, SitoSoym은 파티 결계, 오로라는 회복과 보호막의 빛, 눈뜬 장님은 정밀한 금빛 타격으로 구분한다. 호출 토스트를 겹쳐 표시하지 않는다.
- `damage`는 실제 HP 손실, `heal`은 상한과 회복 금지를 적용한 실제 회복량이다. 회피와 무적, 최대 체력에서의 회복 시도는 가짜 연출을 보내지 않는다. 지속 회복, 흡혈, 물약과 아군 회복도 같은 경로를 사용한다. 다른 아군에게 보내는 회복과 보호막은 시전자에서 대상으로 이어진다.
- `shield-grant`는 실제 생성량, `shield-block`은 실제로 막은 피해량이다. 방어 수치는 피해와 구별해 `방어`로 표시한다. 보호막이 남은 동안에는 초상을 가리지 않는 조용한 유리막을 유지한다.
- 피해 또는 방어 횟수 소진으로 보호막이 없어지면 `shield-break`로 유리막이 부서진다. 초과 피해는 별도의 `damage`로 표시한다. 시간 만료는 `shield-expire`로 조용히 흩어지고 파괴음은 재생하지 않는다. 만료에 따른 회복은 실제 회복량으로 따로 보낸다.
- 지원군이 생성한 보호막과 회복에는 `support`를 유지해 지원군의 기운이 닿는 시점에 표현한다. 파티원 사이의 시전 동작이나 생성음과 중복하지 않는다.
- 캔버스는 화면의 별도 계층에 겹치고 입력을 받지 않는다. 매 프레임 현재 파티 카드의 위치를 읽으므로 200ms 카드 갱신으로 효과가 끊기지 않는다. 보스 무대 높이를 바꾸지 않으며 채팅, 패턴 입력과 대화상자는 효과 위에 유지한다.
- 방, 전투 시작 시각 또는 관문이 달라지면 효과와 재생 중인 음원을 정리한다. 전멸의 마지막 피해는 기존 3초 실패 전환 동안 유지한다. 재접속 스냅샷에는 일회성 효과를 넣지 않으며 중복 식별자와 2.5초 이상 지난 사건은 다시 재생하지 않는다. 숨겨진 화면에서는 소리와 일회성 이동을 중단하고 동작 줄이기 설정을 따른다.
- 생성한 회복과 유리막 알파 텍스처를 사용한다. 새 효과음은 [기존에 출처와 CC0를 확인한 외부 음원](raid-assets.md)으로 제한하며 기존 타격, 치명타, 스킬, 물약과 카운트다운 음원은 유지한다. 회복과 방어가 연속 발생할 때는 숫자와 소리를 묶어 과밀하게 재생하지 않는다.

## 관전

방 목록은 준비 중과 전투 중 파티를 함께 표시하고 `관전`으로 입장한다. 비공개 방은 기존 비밀번호가 필요하며, 인증 및 파티 기능 이용 검사를 동일하게 적용한다. 관전 등록 후 전용 SSE로 같은 무대와 패턴, 파티 HP, 지원군 게이지, 채팅 및 전투 로그를 받는다.

- 관전자 목록은 참가자 목록과 분리한다. 파티 정원, 준비와 포지션, 물약 소모, 보상 및 클리어 기록에 포함하지 않는다.
- 관전 배지를 표시하고 조작 버튼과 개인 선택지는 숨긴다. 공격, 스킬, 물약, 패턴 입력, 투표, 채팅 전송과 재시작은 참가자 검사로 서버에서도 거부한다. 전투 로그를 기본으로 열며 결과 화면에서도 읽을 수 있다.
- 참가 중인 계정은 먼저 파티를 나와야 관전할 수 있다. 새 파티 참가 시 기존 관전을 종료한다. 관전 연결 종료에는 30초 재연결 유예를 두고, 마지막 참가자가 나가 방이 닫히면 관전도 종료한다.

## 관문 컷씬

`proceedToNextPhase()`가 다음 관문을 만들 때 `room.phaseTransition`을 생성한다. `startedAt`, `endsAt`, `id`, 관문 번호, 이전과 다음 보스의 이미지, 배경 및 `fromScene`과 `toScene` 구도가 스냅샷에 포함된다. 전환은 3초이고 `introUntil`을 같은 종료 시각으로 설정한다.

- 서버는 해당 구간의 몬스터 행동, 패턴, 버프 진행과 플레이어의 전투 행동을 기존 `isIntroActive()` 검사로 막는다. 화면만 덮은 상태에서 전투가 진행되면 안 된다.
- 클라이언트는 서버 시각 보정을 사용해 남은 구간만 재생한다. 재접속과 반복 스냅샷으로 컷씬을 처음부터 다시 시작하지 않는다.
- `questDef.phases[].artwork`로 다음 관문의 보스와 배경을 준비 단계부터 미리 읽고 디코딩한다. 숨김 스타일은 `#pqPhaseStage`의 실제 전투 전경에만 적용한다. 컷씬 내부 전경까지 숨기면 배경만 전환되고 종료 순간에 보스가 갑자기 뜨므로 금지한다.
- 컷씬은 `.pq-game-stagewrap` 안에서만 표시한다. 배경과 보스를 한 평면으로 묶고 보스 발 위치를 기준으로 카메라를 움직인다. 안개가 장면 교체를 가린 뒤, 처음부터 불투명한 보스의 실루엣에 조명이 닿고 발밑 안개가 걷히게 한다. 보스만 따로 이동하거나 투명도로 등장시키지 않는다. 2.7초에는 카메라와 조명, 안개가 실제 무대와 같은 상태가 되고, 실제 보스를 복원한 뒤 마지막 0.3초 동안 컷씬 덮개를 걷는다. 관문 이름 외에 설명 문구를 추가하지 않으며 어둠 정화의 이전 장면에는 아직 등장하지 않은 호두 보스를 표시하지 않는다.
- 공격, 스킬, 물약과 지원군을 비활성화한다. 방 나가기와 설정은 계속 사용할 수 있다. 전멸, 결과 화면, 방 이동 시 컷씬 타이머와 오버레이를 제거한다.
- `prefers-reduced-motion: reduce`에서는 이미지 이동과 확대 대신 페이드만 사용한다.
- 마지막 관문은 기존 결과 화면으로 이동한다. 대저택의 본체에서 잔향으로 바뀌는 내부 패턴은 기존 4초 전환 규칙을 유지한다.

## 음악

`public/party.js`의 `RAID_BGM`에 퀘스트 ID별 음원을 등록한다. 배열의 관문 인덱스로 선택하며, 다음 관문 음원이 따로 없으면 첫 음원을 계속 사용한다. 난이도별 퀘스트 ID도 빠짐없이 등록한다.

- 같은 음원이면 `currentTime`과 재생 중인 오디오를 유지한다. 스냅샷이나 관문 변경으로 재시작하거나 음량을 낮추지 않는다.
- 곡이 다르면 새 오디오를 준비하는 동안 기존 곡을 유지한다. 새 곡의 `play()`가 성공한 뒤 1.5초 동안 두 곡을 교차한다. 새 곡은 `sin`, 기존 곡은 `cos` 곡선으로 음량을 바꿔 중간 구간이 갑자기 작아지지 않게 한다.
- 볼륨 설정은 두 오디오에 함께 적용한다. 음소거, 전투 종료, 방 나가기 시 이전 곡과 진행 중인 페이드를 모두 정리한다.
- 자동 재생이 차단되면 마우스나 키보드 입력에서 재시도한다. 늦게 완료된 재생 요청이 떠난 방의 음악을 다시 켜면 안 된다.
- 기존 3초 전멸 연출의 감속과 음량 감소를 유지한다. 전멸 연출이 일반 스냅샷이나 음악 교차에 의해 초기화되면 안 된다.
- 음원은 기존 `/rpg-ui` 자산 경로를 사용한다. 레이드용 파일과 필드용 파일을 구분한다. `부타게임H.mp3`는 헬필드 음원이다.

## 추가 레이드 확인

기존 `tests/mansion_raid.test.js`에서 실제 서버 스냅샷과 관문 전환 중 행동 차단을 검증한다. `tests/party_music.test.js`에서 음원 등록, 같은 곡 유지, 교차 중 음량, 음소거와 종료 처리를 검증한다. 브라우저에서는 패턴 카드의 중복, 모바일 조작부, 컷씬 종료와 재접속을 확인한다. 테스트는 운영 DB와 S3 쓰기 없이 실행한다.

시각 구성은 Claude Opus 5.5의 디자인 검토를 반영했다.
