# 레이드 공통 패턴 표시와 관문 전환

잉여왕, 흑화 호두, E세계대저택은 `partyquest.js`의 전투 엔진과 `public/party.js`의 전투 화면을 공유한다. 새 레이드도 아래 규칙을 사용한다. 보상, 피해량, 패턴 발동 조건, 해금 조건은 이 연출 계층에서 변경하지 않는다.

## 전투 계산

타격의 수치 판정은 필드, 훈련장, 월드보스와 PVP에서 사용하는 `rpgenius.calculateAttackHitResult()`를 호출한다. 레이드의 `calculateOutgoingDamage()`는 역할 보정, 전투 중 버프와 대상 디버프를 준비하고 공통 함수의 결과를 기존 레이드 이벤트 형식으로 변환한다.

- 치명타, 방어력과 관통력, 연격, 속성, 고정 피해, 추가 피해, 타격별 반올림을 레이드에 별도 구현하지 않는다. 몬스터의 연격, 치명타, 방어 계산과 피해 변동도 `rpgenius`의 공통 함수를 사용한다.
- 장비의 타격 전후 처리는 공통 계산기의 `beforeAttackUnit`과 `afterAttackUnit`에 연결한다. 고정 다단 공격은 하나의 공격으로, 연격은 타격마다 별도의 공격으로 장비를 처리한다. `separateBasicAttackHits`를 지정한 일반 공격 스킬은 실제 타격 수로 공격 횟수를 센다.
- 잡몹 단계는 `room.mobMonster`에 대상 상태를 유지한다. 기본 공격, 스킬, 소환수와 장비 효과는 `getPhaseCombatMonster()`로 같은 대상을 가져온다. 공격마다 임시 몬스터를 만들면 화상과 방어 감소가 사라지므로 사용하지 않는다.
- 화상, 겁화와 유서새김은 잡몹, 엘리트와 보스 모두 `stepMonsterDebuffs()`에서 진행한다. 타격은 공통 피해 계산을 거치고 처치 수, 피해 통계와 로그에 반영한다. 화상과 겁화는 화속성이며 치명타가 발생하지 않는다. 이미 계산한 그림자 공격은 `precalculatedDamage`로 재계산을 막는다.
- 지속 피해와 소환 공격은 장비 발동, 공격 횟수, 공격 시 회복이나 다음 직접 공격의 버프를 소모하지 않는다. 관문 전환과 전투 종료에서는 이전 대상 상태를 정리하고, 지속 피해로 관문이 끝나면 해당 틱도 중단한다.
- 레이드의 역할, 패턴, 보호막과 관문 규칙은 서버의 레이드 계층에서 처리한다. 실제 피해를 적용할 때 기존 보스 기믹 판정을 거친다.

`tests/mansion_raid.test.js`는 같은 스탯과 난수로 일반 몬스터, 엘리트와 보스의 공통 계산 결과를 비교하고 잡몹의 화상, 유서새김, 보스의 화속성 지속 피해와 관문 상태 정리를 검증한다. 장비 효과를 추가할 때 이 경로에서도 유지와 만료, 간접 공격의 재발동 여부를 확인한다.

## 패턴 HUD

보스 스테이지 아래 `#pqMansionRoot`와 `MansionRaidUI.update()`를 공통 HUD로 사용한다. 파일명은 기존 대저택 구현을 유지하지만, `public/mansion-raid.js`와 `public/mansion-raid.css`가 모든 레이드의 패턴 카드, 대상 강조, 타이머를 담당한다.

- 카드에는 패턴 이름, 기존에 공개된 공식 문구, 대상 또는 참여 상태, 남은 시간만 표시한다. 새로운 대응법, 성공 범위, 추천 행동을 임의로 덧붙이지 않는다.
- 타이머는 오른쪽에 0.1초 단위로 표시한다. 진행선과 종료 직전의 색 변화도 같은 컴포넌트가 처리한다.
- 나에게 지정된 패턴은 같은 금색 배지와 대상 표시로 강조한다. 색만으로 대상을 구분하지 않는다.
- 같은 사건은 같은 `id`를 유지한다. SSE 갱신은 카드 내용만 변경하고, 클릭 중인 버튼과 초점을 다시 만들지 않는다. 새 시전에는 새 `id`를 부여한다.
- 종료된 사건은 서버 목록에서 제거한다. 상시 표식은 `remain: null`로 보내며, 제한 시간이나 마감 표시를 만들지 않는다.
- 보스 체력바 아래의 `nextPattern` 문구를 다시 표시하지 않는다. 패턴 이름과 시간이 두 곳에 중복해서 나오지 않게 한다.
- 좁은 화면에서는 보스 영역과 패턴 패널이 공간을 나눠 사용한다. 파티원, 공격, 스킬, 물약, 지원군 조작부는 화면 안에 유지한다.

일반 보스의 공개 신호는 `serializeBossPatternEvents()`에서 `monster.patternEvents`로 직렬화한다. 대저택은 기존 `monster.mansion.events`와 입력 기믹을 유지한다. 두 경우 모두 `updateRaidPatterns()`를 거쳐 같은 HUD에 도달한다.

```js
{
  id: 'cast:flame:3', // 이 사건 동안 유지되는 식별자
  kind: 'raidCue',
  label: '화염 폭발',
  tag: '시전',
  remain: 2.4,       // 초. 상시 표식은 null
  duration: 3,
  targets: [],       // 이미 공개된 지정 대상만 포함
  responded: [],
  requiresResponse: false
}
```

사용자 입력이 필요한 새로운 기믹은 `KINDS`에 입력 패널을 추가하고, 기존 `act()`의 중복 요청 방지와 카드 갱신 방식을 사용한다. 피해 판정과 성공 조건은 서버 보스 핸들러에 둔다. `onFinish` 같은 함수나 서버 내부 상태를 공개 데이터에 포함하지 않는다.

## 관문 컷씬

`proceedToNextPhase()`가 다음 관문을 만들 때 `room.phaseTransition`을 생성한다. `startedAt`, `endsAt`, `id`, 관문 번호, 이전 보스 이미지와 다음 보스 이미지가 스냅샷에 포함된다. 전환은 3초이고 `introUntil`을 같은 종료 시각으로 설정한다.

- 서버는 해당 구간의 몬스터 행동, 패턴, 버프 진행과 플레이어의 전투 행동을 기존 `isIntroActive()` 검사로 막는다. 화면만 덮은 상태에서 전투가 진행되면 안 된다.
- 클라이언트는 서버 시각 보정을 사용해 남은 구간만 재생한다. 재접속과 반복 스냅샷으로 컷씬을 처음부터 다시 시작하지 않는다.
- 컷씬은 `.pq-game-stagewrap` 안에서만 표시한다. 이전 보스가 어두워지고 다음 보스와 관문 이름이 등장한 뒤 페이드로 전투 화면에 연결한다. 섬광, 과한 흔들림, 설명 문구를 추가하지 않는다.
- 공격, 스킬, 물약과 지원군을 비활성화한다. 방 나가기와 설정은 계속 사용할 수 있다. 전멸, 결과 화면, 방 이동 시 컷씬 타이머와 오버레이를 제거한다.
- `prefers-reduced-motion: reduce`에서는 이미지 이동과 확대 대신 페이드만 사용한다.
- 마지막 관문은 기존 결과 화면으로 이동한다. 대저택의 본체에서 잔향으로 바뀌는 내부 패턴은 기존 4초 전환 규칙을 유지한다.

## 음악

`public/party.js`의 `RAID_BGM`에 퀘스트 ID별 음원을 등록한다. 배열의 관문 인덱스로 선택하며, 다음 관문 음원이 따로 없으면 첫 음원을 계속 사용한다. 난이도별 퀘스트 ID도 빠짐없이 등록한다.

- 같은 음원이면 `currentTime`과 재생 중인 오디오를 유지한다. 스냅샷이나 관문 변경으로 재시작하거나 음량을 낮추지 않는다.
- 곡이 다르면 새 오디오를 준비하는 동안 기존 곡을 유지한다. 새 곡의 `play()`가 성공한 뒤 1.5초 동안 두 곡을 교차한다. 새 곡은 `sin`, 기존 곡은 `cos` 곡선으로 음량을 바꿔 중간 구간이 갑자기 작아지지 않게 한다.
- 볼륨 설정은 두 오디오에 함께 적용한다. 음소거, 전투 종료, 방 나가기 시 이전 곡과 진행 중인 페이드를 모두 정리한다.
- 자동 재생이 차단되면 마우스나 키보드 입력에서 재시도한다. 늦게 완료된 재생 요청이 떠난 방의 음악을 다시 켜면 안 된다.
- 기존 3초 전멸 연출의 감속과 음량 감소를 유지한다. 전멸 연출이 일반 스냅샷이나 음악 교차에 의해 초기화되면 안 된다.
- 음원은 기존 `/rpg-ui` 자산 경로를 사용한다. 레이드용 파일과 필드용 파일을 구분한다. `부타게임H.mp3`는 헬필드 음원이다.

## 추가 레이드 확인

기존 `tests/mansion_raid.test.js`에서 실제 서버 스냅샷과 관문 전환 중 행동 차단을 검증한다. `tests/party_music.test.js`에서 음원 등록, 같은 곡 유지, 교차 중 음량, 음소거와 종료 처리를 검증한다. 브라우저에서는 패턴 카드의 중복, 모바일 조작부, 컷씬 종료와 재접속을 확인한다. 테스트는 운영 DB와 S3 쓰기 없이 실행한다.

시각 구성은 Claude Opus 5.5의 디자인 검토를 반영했다.
