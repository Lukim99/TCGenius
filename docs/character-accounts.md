# 계정과 캐릭터 분리

기존 계정은 첫 웹 로그인 또는 게임 채팅 명령에서 기존 사용자 ID를 유지한 1번 캐릭터로 전환된다. 계정 공용 정보는 `rpgenius_user`의 `account:<기존 ID>` 행으로 옮기며, 계정 생성과 기존 행 변경을 하나의 트랜잭션으로 저장한다. 서버 시작만으로 사용자나 운영 상품을 변경하지 않는다.

## 데이터 범위

| 계정 공용 | 캐릭터별 |
| --- | --- |
| 로그인 이름, 로그인 기기, OTP, 관리자 권한 | 캐릭터 이름, 레벨, 경험치, HP, MP |
| 골드, 가넷, 포인트, 마일리지, 누적 포인트 | 카드, 장비, 펫, 일반 아이템, 아바타, 프리셋 |
| 출석, 축복, 환생, 전직 환생, 칭호 보유와 진행 | 퀘스트, 레벨 보상, 구매 스탯, 가방, 천장 |
| 이벤트 참여와 수령, 이벤트 아이템, 쿠폰 사용 | 레이드 보상 횟수, 낙원, 낚시, PvP, 우편 |
| 상점 구매 제한, 사냥 골드 한도 | 초보자 지원 패키지 구매 제한 |

구체적인 공유 필드는 `character_accounts.js`의 `SHARED_FIELDS`에 있다. 이벤트 아이템은 운영 아이템 정의로 분류하며 `accountScope: "account"` 또는 `"character"`가 있으면 그 설정을 우선한다. 상점은 `purchaseScope` 설정을 우선하고, 설정이 없는 초보자 지원 패키지만 캐릭터별 제한으로 취급한다. 기존 구매 기록을 보존한다. 단, `이벤트 리스트 종이`는 사용자 결정에 따른 예외로, 공유 분류 설정과 관계없이 캐릭터별 소지품으로 보관한다.

캐릭터 이름을 변경해도 로그인 이름과 외부 포인트 연동 계정은 바뀌지 않는다. 이전 캐릭터 이름은 기존 우편, 거래, 월드보스 기록이 같은 캐릭터를 찾도록 유지하며 재사용하지 않는다.

이름 변경은 해당 캐릭터의 변경권 1개를 우선 사용하고, 없으면 확인한 300P를 사용한다. 확인창을 연 뒤 변경권 보유 상태가 바뀌면 포인트를 대신 차감하지 않고 비용을 다시 확인하도록 한다.

게임 화면의 포인트, 충전, OTP, 관리자 접근과 로그아웃은 계정 아이콘의 메뉴 안에서 이용한다. 기존 충전과 인증 처리 함수를 유지한다. 캐릭터 선택 목록은 서버의 실제 카드 등급을 포함한 이름을 표시한다.

캐릭터 선택 목록의 레벨은 닉네임 앞에 작게 표시한다. 자리 확장은 선택한 캐릭터가 가진 캐릭터 슬롯 확장권 1개를 우선 사용하고, 없으면 기존 800P를 사용한다. 확인창에 소유자와 정확한 비용을 표시하며, 확인 뒤 확장권 보유 상태가 바뀌면 다른 결제 수단으로 바꾸지 않고 재확인을 요청한다. 확장권 차감과 한 칸 확장은 같은 트랜잭션으로 저장한다.

## 캐릭터 생성

새 캐릭터 생성과 아직 시작 카드를 정하지 않은 캐릭터의 첫 선택은 전체 화면의 초상화 회랑을 사용한다. 기존 글꼴을 유지하며 17개 캐릭터의 프레임 없는 사각 아이콘으로 선택한다. 일반, 전직, 각성 토글로 표지와 능력 미리보기를 함께 바꾸며 16:9 원본을 자르지 않는다. 별도 확대 기능과 시작 카드 옆 성급 표시는 없다. 같은 그림을 흐린 배경으로 사용해 화면 비율이 달라도 화면 전체를 채운다. 모바일 아이콘은 좌우로 넘기며, 아주 짧은 세로 화면은 아이콘 옆에 이름을 붙여 소개 영역을 확보한다. 해당 화면의 이름 입력 단계에서는 표지를 접어 입력 공간을 남긴다.

캐릭터 이름 아래에는 일반 표지에서 추출한 소개를 표시한다. 소개는 `CharacterIntroductions.json`의 읽기 전용 문구이며 전직, 각성 표지로 바꿔도 유지한다. 캐릭터와 설명을 살펴본 뒤 이름을 입력하고 생성한다. 입력 단계에서 돌아가도 이름은 유지된다. 스킬 설명은 실제 스킬 정의의 5성 수치와 기본 자원 소모량, 재사용 시간을 표시하고 고유 슬롯 효과도 현재 계산과 같은 정의를 사용한다. 일반은 기본 스킬, 전직은 기본 스킬과 궁극기, 각성은 기본 스킬과 궁극기에 각성 패시브를 추가해서 보여 준다. 슬롯 패시브는 타입마다 실제 전투에서 사용하는 해당 타입의 정의로 교체한다. 켄시처럼 각성에 따라 스킬 문구가 달라지는 경우도 실제 포매터를 사용한다. 토글은 미리보기이며 지급할 일반 5성 카드를 바꾸지 않는다. 원본 표지에 인쇄된 과거 능력 문구는 그림 그대로 보존하며, 별도 능력 설명은 현재 게임 데이터를 기준으로 한다. 이미지 로드가 늦어져도 이전 캐릭터나 이전 종류의 표지가 현재 선택을 덮어쓰지 않는다.

시작 카드는 5성 일반 카드로 지급한다. 부캐 생성과 기존 미선택 캐릭터, 채팅의 첫 카드 선택에 공통 지급 함수를 사용한다. 기존에 지급된 카드의 성급은 변경하지 않는다. 기본 레벨과 초보자 키트 지급, 중복 요청 방지 규칙을 유지한다. 안내 데이터를 만들기 위해 운영 DB에 새 읽기나 쓰기를 추가하지 않는다.

Fable 5.2에 이미지와 요구사항을 전달한 디자인 자문 1회를 반영했다. Claude에 파일 수정이나 테스트를 맡기지 않았으며 보고된 비용은 $0.118472다. 클릭 효과음은 기존 CC0 녹음 파일을 명시적인 선택에만 사용한다. 같은 캐릭터 재선택과 마우스 올리기에는 소리를 내지 않고 빠른 키 반복에서도 녹음이 겹치지 않게 한다. 반복 물소리와 밤 환경음은 제거했고 Suno에서 새로 생성한 배경 음악 한 곡을 사용한다. 출처와 다운로드 권한, 생성 지시문은 `public/assets/account-stage/CREDITS.md`에 기록한다.

## 전환과 자산 보호

동시에 플레이하는 캐릭터는 계정당 하나다. 진행 중인 전투, 탐험, 거래, 미완료 선택이 있으면 전환을 막고, 낚시는 전환할 때 종료한다. 이전 화면은 캐릭터 ID와 선택 버전을 검사해 새 캐릭터에 명령을 보내지 못하게 한다.

전송은 같은 계정의 다른 캐릭터에게 카드 또는 초월 장비 1개를 이동한다. 해당 전송기 1개를 소모하며 카드 거래권을 쓰지 않는다. 물품 목록이 바뀌면 다시 선택해야 한다. 잠금과 장착 상태를 확인하고 강화, 잠재, 고유 ID를 보존한다. 카드의 캐릭터별 아바타 참조는 이전하지 않는다.

물품 이전은 전체 화면에서 물품 선택, 받는 캐릭터 선택, 최종 확인 순으로 진행한다. 넓은 화면에서는 목록과 선택한 물품 상세, 캐릭터 목록을 함께 보여 준다. 카드는 이미지와 성급, 타입, 아바타를 포함한 이름만 표시한다. 소지품 번호와 중복 성급 안내, 스킬 상세는 표시하지 않는다. 할로윈 아바타 이름은 목록과 상세, 확인 화면에서 기존 주황색 특수 표시를 공유한다. 장비 상세는 기존 거래와 인벤토리에서 사용하는 서버 표시 함수를 재사용하며 강화, 초월 단계, 실제 능력치와 잠재, 고유 효과를 보여 준다. 별도 DB 조회를 추가하지 않는다. 전송기는 제공된 원본 이미지를 사용하고, 성공 응답을 받은 뒤에만 물품이 받는 캐릭터로 이동하는 연출을 재생한다. 전송 중에는 중복 제출과 창 닫기를 막으며, 응답 유실 후 재시도에는 같은 요청 번호를 사용한다. 움직임 줄이기 설정에서는 짧은 페이드로 대체한다.

기존 카드 장착 슬롯은 폐지한다. 현재 플레이하는 캐릭터가 메인이며 같은 계정의 다른 부캐를 최대 5명 직접 지정한다. 부캐의 메인 카드가 5성 이상이어야 한다. 슬롯끼리는 타입과 무관하게 같은 기본 캐릭터를 중복 지정할 수 없고, 메인과 슬롯 하나는 타입이 다를 때만 겹칠 수 있다. 기존 슬롯 카드는 최초 계정 전환 시 속성 그대로 인벤토리로 모두 반환하며 인벤토리 공간 부족으로 삭제하지 않는다.

메인 카드와 지정한 부캐들의 메인 카드에서 고유 슬롯 효과를 합산한다. 등급별 공격력 증가는 부캐 슬롯에만 적용한다. 현재 플레이 중인 메인 캐릭터와 유효하게 지정한 부캐들의 레벨 합만큼 체력이 증가하고, 레벨 합을 1000으로 나눈 비율만큼 골드, 경험치, 드롭 보너스가 증가한다. 부캐의 레벨이나 메인 카드가 바뀌면 캐시에서 최신 값을 계산하며 다른 캐릭터 레코드에 복제 저장하지 않는다. 카드 변경으로 성급이나 중복 조건을 위반한 슬롯은 효과를 적용하지 않고 슬롯 연결 화면에 사유를 표시한다.

프리셋과 PvP 방어 덱도 슬롯 카드 대신 부캐 ID를 저장한다. 슬롯의 카드는 소유자 인벤토리에 복제하거나 직접 아바타를 변경할 수 없으며, 부캐를 플레이하며 그 부캐의 메인 카드를 변경한다. 메인 카드 변경과 프리셋, PvP에서는 동일한 중복 규칙을 검증한다.

슬롯 연결 화면은 기존 글꼴을 유지한 호수 회랑으로 구성한다. 플레이 중인 메인은 별도 위치에 표시하고, 부캐 슬롯에는 닉네임 대신 성급, 타입, 아바타를 포함한 카드 이름과 실제 슬롯 효과를 표시한다. 이름은 생략하지 않으며 성급과 타입, 카드 이름을 의미 단위로 나눈다. 고유 효과와 등급 공격력을 구분하고, 감소 효과와 메인 조건이 충족되지 않은 효과도 표시한다. 효과 정의와 등급 보너스는 실제 전투 계산과 공유하며 운영 데이터를 수정하지 않는다.

슬롯 번호 5개를 통해 편집할 슬롯을 고른 뒤 부캐를 선택한다. 연결 전에는 해당 슬롯에서 그림과 효과를 미리 보여 주고, 연결 버튼을 눌렀을 때만 저장한다. 모바일에서는 번호 5개를 고정하고 슬롯과 부캐 목록을 좌우로 넘긴다. 낮은 화면에서는 그림 옆에 이름과 효과를 배치한다. 게임 정보 창에서 변경한 슬롯 번호도 연결 화면까지 전달한다. 이 구성은 Fable 5.2에 화면과 요구사항만 전달한 1회 디자인 자문을 바탕으로 구현했으며, Claude에 코드 작업이나 테스트를 맡기지 않았다.

켄시의 고정 슬롯 효과는 일반 치명타 피해량 +10%, 전직 치명타 피해량 +5%와 치명타 확률 +5%, 각성 치명타 피해량 +15%와 치명타 확률 -5%, 광폭 치명타 확률 +10%다. 기존 패시브와 스킬 효과는 그대로 유지한다.

생성, 전환, 확장, 이름 변경, 전송, 연결에는 요청 번호별 처리 기록을 저장한다. 응답이 유실되어 같은 요청을 재전송해도 같은 변경을 두 번 적용하지 않는다. 포인트 사용 기록은 기존 계정 ID로 집계하고 사용한 캐릭터 정보를 추가로 남긴다.

## DB 요청 절감

일반 사냥과 낚시의 기존 지연 저장을 유지해 계정 지갑과 캐릭터 변경을 모은다. 값이 달라지지 않으면 쓰지 않고, 단일 행 변경은 조건부 갱신 한 번으로 저장한다. 자산이 여러 행에 걸치는 작업만 트랜잭션으로 처리한다. 충돌 시 최신 잔액을 덮어쓰지 않는다.

캐릭터 목록과 랭킹은 사용자 메모리 캐시를 이용한다. 랭킹은 캐릭터별로 표시하고 마을 전투력으로 계산하며, 60초 캐시와 동시 계산 합치기를 사용한다. 계정 분리로 필요한 저장량 자체는 늘 수 있으므로 실제 요금이 동일하다는 보장은 아니다.

## 운영 적용

이 변경은 별도 브랜치에서 검증한다. 운영 배포나 상품 등록은 코드 커밋과 구분한다.

### 이벤트 리스트 종이의 캐릭터별 보관 전환

기존 공유 보관분은 사용자 결정에 따라 각 계정의 `characterNumber: 1` 캐릭터로 옮긴다. 현재 선택한 캐릭터나 목록 순서를 기준으로 하지 않는다. 이후 획득분은 획득한 캐릭터가 보유한다.

`node scripts/migrate_event_list_paper.js`는 운영 Item과 실제 보관 수량, 1번 캐릭터를 읽어 이전 예정만 출력한다. 환경 파일이 다른 폴더에 있으면 `--env-dir=<폴더>`를 지정한다. 운영 Item 정의나 다른 소지품은 수정하지 않는다.

적용할 때는 기존 서버의 저장을 완료하고 서버를 중지한 상태에서 수정 코드를 준비한 뒤 `node scripts/migrate_event_list_paper.js --apply`를 명시적으로 실행하고, 검증 완료 후 수정 서버를 시작한다. 구버전 서버가 실행 중이면 종이를 다시 공유 보관할 수 있으며, 이전 전 새 서버를 시작하면 소지품 저장 충돌이 발생할 수 있다. 시작이나 배포 스크립트에서 이 이전을 자동 실행하지 않는다.

변경 전 자료는 OS 임시 폴더에 백업한다. 계정 공유분 차감과 1번 캐릭터 지급은 계정별 단일 트랜잭션으로 수행하고 귀속 수량을 합산한다. 읽은 소지품이나 계정 소속이 바뀌면 덮어쓰지 않고 중단하며, 저장 후 다시 읽어 확인한다. 이미 이전된 계정은 재실행해도 다시 지급하지 않는다. 일부 계정 처리 후 중단됐다면 원인을 해결하고 같은 명령을 재실행한다.

### 아이템 및 상품 등록

1. 배포 전 사용자 테이블의 복구 가능한 백업을 확보한다. 기존 사용자 ID를 보존하는 점과 기존 로그인, 포인트 연동을 확인한다.
2. `node scripts/register_character_items.js`는 현재 운영 `Item`과 `Shop`을 읽어 변경 예정만 출력한다. 기존 항목, 상품 ID, 구성, 가격을 덮어쓰지 않는다.
3. 등록을 적용할 때만 `node scripts/register_character_items.js --apply`를 실행한다. 누락된 닉네임 변경권, 카드 전송기, 장비 전송기, 캐릭터 슬롯 확장권과 닉네임 변경권 300P 상품을 추가한다. 상품을 변경하지 않고 아이템만 등록하려면 `--items-only`를 함께 지정한다. 변경 전 자료를 OS 임시 폴더에 백업하고, 동시 운영 변경이 있으면 적용을 중단한다.
4. 전송기는 기존 관리자 지급 기능을 사용할 수 있다. 승인되지 않은 판매 가격이나 지정 캐릭터 변환석 주머니 상시 판매 상품은 추가하지 않는다.

2026-11-23에는 명시적으로 요청된 네 아이템만 `--items-only --apply`로 운영 Item에 추가했다. 기존 항목과 인덱스, 상품과 판매 가격은 변경하지 않았다. 백업은 `C:/Users/dodom/AppData/Local/Temp/tcgenius-shop-backups/character-items-1795428567386.json`이다. 코드 배포는 별도이며 이 등록만으로 새 화면이나 확장권 사용 기능이 배포되지는 않는다.

같은 날 `scripts/migrate_character_account_assets.js`로 사용자가 제공한 17명 일반 및 전직 표지 34장과 티켓 이미지 4장을 기존 S3 자산 경로에 반영했다. 기존 표지 31장은 교체했고 3장은 이미 동일했으며, 각성 표지는 변경하지 않았다. 38개 객체를 다시 받아 원본 바이트와 MIME 형식을 확인했고 로컬 자산도 같은 파일로 연결했다. `scripts/character_account_assets.json`에 키, 크기, SHA-256을 기록했다. 이전 파일 백업은 `C:/Users/dodom/AppData/Local/Temp/rpgenius-character-assets-hN5Dvn`이다. 표지 URL에는 파일 수정 시각을 붙여 브라우저의 이전 이미지 캐시와 구분한다. 이전 일반 표지에서 추출한 캐릭터 소개는 유지한다.

계정 전환 후에는 이전 서버 버전으로 코드만 되돌리면 공유 지갑을 제대로 읽지 못한다. 문제가 생기면 이 스키마를 이해하는 수정 버전을 사용하거나, 이후 플레이 기록의 보존 방안을 정한 뒤 데이터를 복구해야 한다. 새 스키마가 생긴 운영 DB에 예전 서버를 그대로 연결하지 않는다.

## 확인한 동작

물품 이전과 확장권 변경에서는 계정 및 캐릭터 API 테스트 37개가 통과했다. 격리 서버의 실제 화면에서 카드와 초월 장비 각각 한 개 이전, 전송기 한 개 차감, 연속 클릭 방지, 확장권 한 개 및 800P 확장을 확인했다. 성공 응답을 끊은 뒤 재시도해도 같은 요청 번호로 한 번만 이전됐다. 목록 읽기 실패 후 재시도, 창 닫기와 다른 창의 스타일 복구, 카드 정보 축약, 레벨의 닉네임 앞 배치, 할로윈 주황색 표시를 확인했다. API가 반환하는 일반 및 전직 표지 34개와 아이템 아이콘 4개는 제공 원본과 바이트 단위로 일치했다.

물품 화면은 Chrome, Edge, Firefox, WebKit에서 320×480, 390×900, 640×360, 768×1024, 1024×768, 1440×900, 2560×1080, 3840×2160으로 점검했다. 후속 카드 정보 축약과 레벨, 할로윈 표시 변경 후에는 네 브라우저에서 320×480, 390×900, 640×360, 1024×768, 1440×900을 다시 확인했다. 가로 넘침과 실행 버튼 이탈, 페이지 스크립트 오류가 없었다. 장비 상세는 내부에서 스크롤하며, 작은 세로 화면에서는 살펴보는 동안 상단 무대를 접는다. 실제 모바일 기기에서의 키보드와 GPU 성능은 측정하지 않았다.

격리 DB를 사용하는 기존 테스트와 `tests/character_accounts.test.js`, `tests/character_routes.test.js`에서 첫 전환, 공유 범위, 중복 요청, 오래된 화면, 포인트와 아이템 전송, 우편 수령과 반송, 중복 슬롯, 슬롯 연결, 마을 전투력, 구매 제한, 사냥 한도를 검증한다. 테스트는 운영 DB에 쓰지 않는다.

선택한 회귀 테스트 190개가 통과했고 선택 실행 브라우저 테스트 2개는 건너뛰었다. 이후 이름 변경 결제 방식 검사를 추가한 캐릭터 API 테스트 22개도 통과했다. 전체 저장소 테스트가 모두 통과했다는 의미는 아니다. 변경 전 원본에서도 실패한 `general_field_parity.test.js`의 정적 문자열 검사와 `ilion.test.js`의 `13종 보주` 데이터 순서 가정은 이번 회귀 실행에서 제외했다.

실제 서버와 격리 DB를 연결한 브라우저에서는 로그인, 직접 슬롯 연결, 카드 이전과 전송기 차감, 변경권과 포인트 각각의 이름 변경, 10자 이름 생성, 800P 확장, 캐릭터 전환, 계정 메뉴와 OTP 설정 창을 확인했다. 외부 포인트 잔액도 메모리로 격리한 100P 충전에서 이름 변경 후에도 원래 계정 잔액을 사용하고 공용 포인트가 증가하는 것을 확인했다. 실제 결제나 운영 API를 사용하지 않았다.

최종 화면을 Chrome, Edge, Firefox, WebKit에서 각각 320×568, 390×844, 768×1024, 1440×900, 2560×1080, 3840×2160, 844×390으로 확인했다. 가로 넘침, 시작 버튼의 화면 이탈, 페이지 스크립트 오류와 실패한 리소스 요청은 없었다. 별도로 WebGL 사용 불가와 컨텍스트 손실 후 복구, 움직임 줄이기를 확인했다. 실제 iOS 기기나 저사양 휴대폰의 GPU 성능은 측정하지 않았다.

부캐 자체를 슬롯으로 사용하는 수정에서는 선택한 회귀 테스트 157개가 통과했고 선택 실행 브라우저 테스트 1개를 건너뛰었다. 최종 계정, 캐릭터 API, PvP 테스트 35개도 통과했다. 메인 고유 슬롯 효과, 메인 등급 공격력 제외, 5성 제한, 슬롯 5명과 중복 규칙, 레벨 변경 반영, 카드 보존, 프리셋 표시와 PvP 방어 저장을 검증했다. 별도로 실행한 `unique_avatar.test.js`의 HTTP 테스트는 기존 격리 픽스처에 계정 캐시가 없어 중단했으며 통과 수에 포함하지 않았다.

수정한 슬롯 화면도 위 4개 브라우저와 7개 화면 크기에서 기존 글꼴, 슬롯 번호 5개, 좌우 스크롤, 연결 버튼, 오류 표시, 키보드 이동을 확인했다. 카드 이름과 효과의 가로 잘림, 후보 항목의 세로 잘림, 말줄임표가 없음을 확인했고 긴 수영장 아바타 이름도 실제 부캐를 연결해 확인했다. 연결 전 미리보기가 DB에 저장되지 않는 점, 교체와 해제, 좌우 스크롤 후 편집 슬롯 변경을 실제 화면에서 확인했다. 표시 수치의 검증을 추가한 회귀 테스트는 157개 통과와 선택 실행 브라우저 테스트 1개 건너뜀이다.

캐릭터 선택과 슬롯 변경에는 첨벙 소리를 재생하지 않고 게임 시작 때만 기존 음량으로 한 번 재생하며, 진입 전환은 회전 중 화면을 어둡게 덮고 다음 장면을 드러낸다.

캐릭터 생성 변경은 선택 회귀 테스트 158개 통과, 선택 실행 브라우저 테스트 1개 건너뜀으로 확인했다. Chrome, Edge, Firefox, WebKit에서 320×480, 320×568, 390×844, 768×1024, 1440×900, 2560×1080, 3840×2160, 844×390을 점검했다. 전체 화면 크기, 원본 표지 비율, 긴 이름과 설명, 이름 입력 단계, 키보드 이동과 표지 확대, 다른 창으로 돌아왔을 때의 배치를 확인했다. WebKit의 화면 크기 변경 후 높이 문제를 수정해 재검증했다.

격리 DB에 연결한 실제 화면에서 17개 캐릭터의 표지와 설명, 오래 걸리는 이전 이미지 요청, 잘못된 이름과 이름 중복 오류, 생성 중 연속 제출을 확인했다. 새 키노 캐릭터는 생성 요청 1회로 레벨 1, 5성 일반 카드가 지급되었고 공유 지갑은 변하지 않았다. 실제 모바일 기기의 키보드와 GPU 성능은 측정하지 않았다.

일반 표지 소개 추출, 표지 토글, Suno BGM 후속 변경에서는 계정과 캐릭터 API 테스트 35개가 통과했다. Chrome, Edge, Firefox, WebKit에서 각각 320×480, 320×568, 390×844, 768×1024, 640×360, 844×390, 1024×768, 1440×900, 2560×1080, 3840×2160의 배치, 원본 표지 비율, 생성 버튼 위치와 이름 입력을 확인했다. 이번 변경으로 표지 확대 기능은 제거했다.

실제 격리 서버에서 17개의 일반 소개와 51개의 표지를 전환하고, 토글 전후 소개와 능력 설명이 유지되는지 확인했다. 아이콘 응답 17개는 프레임 없는 원본 파일과 바이트 단위로 일치했다. 늦은 이전 표지 응답도 현재 선택을 덮지 않았다. 각성 표지를 본 뒤 실제 생성한 키노는 일반 5성, 레벨 1이며 요청은 1회, 공용 지갑은 그대로였다. Chrome에서 BGM 연속 재생, 음소거, 이어 재생, 곡 끝 반복과 환경음 요청 부재를 확인했고 Chrome, Firefox, WebKit의 로그인 화면에서 첫 입력 재생과 저장된 음소거 설정도 확인했다. 실제 모바일 기기에서의 청감, 키보드와 GPU 성능은 별도 확인하지 않았다.

이벤트 리스트 종이 분리와 메인 레벨 보너스 변경은 격리 DB 테스트 58개로 확인했다. 메인만 있는 경우, 부캐 5명, 무효 슬롯과 중복 제외, 캐릭터 전환, 실제 체력과 사냥 골드·경험치·드롭, PvP 방어 기록, 파견 회귀를 포함한다. 기존 종이 이전은 수량과 귀속 보존, 1번 캐릭터 검증, 재실행 시 중복 지급 방지를 검사했다. 운영 읽기 점검에서 14개 계정의 22개와 각 계정의 1번 캐릭터를 확인했으며, 실제 이전은 수정 코드 배포와 함께 별도로 실행해야 한다.
