# 포인트 광산 이벤트

윷놀이 메뉴를 포인트 광산으로 교체했다. 기존 윷놀이 조회·던지기 API는 종료 응답(410)을 반환하고, 송편 사용도 차감 없이 거절한다. 기존 윷·송편 보유량과 `yutEvent` 진행 기록은 보존한다. 이전 `윷놀이`·`캡슐` 탭 링크와 배너 대상은 광산 화면으로 연결한다.

코드 구현과 운영 데이터 등록을 완료했다. **운영 코드 배포와 서버 재시작은 수행하지 않았으므로, 실서비스 이벤트 전환은 새 코드 적용 후 이루어진다.**

## 이용 규칙

- 필드 사냥에서 송편 대신 `곡괭이 상자 열쇠`를 지급한다. 기존 송편의 사냥 조건과 레벨·드랍 보정을 유지하며, 기본 확률은 10%, 하루 한도는 2개다. 한국 자정에 한도를 갱신한다. 이미 보유한 열쇠와 오늘의 획득 기록은 보존한다.
- 일반 상점의 기존 송편 상품을 열쇠 1개로 교체했다. 가격은 기존 100골드이고, 일일 구매 한도는 1개다. 같은 상품 ID를 유지해 오늘 이미 송편을 구매한 기록도 이 한도에 포함된다. 포인트 상점에서는 열쇠를 개당 계정 포인트 100P에 구매할 수 있으며 별도 구매 한도가 없다.
- 열쇠 1개로 상자 1개를 열어 16종 중 곡괭이 1개를 받는다. 같은 종류는 남은 내구도와 최대 내구도를 합산해 한 칸에 보관한다. 기존에 따로 보유하던 곡괭이도 내구도와 장착 종류를 보존해 합산하며, 새 행동을 저장할 때 합산 상태를 함께 저장한다. 상자 확률은 화면에서 확인할 수 있다.
- 채굴 1회마다 내구도 1을 소모하고 광물 1개를 얻는다. 서버가 최소 640ms 간격을 확인한다. 곡괭이에 따라 채굴 가능한 광물과 확률이 달라진다.
- 수리 기능은 종료했다. 내구도가 소진되면 같은 종류의 곡괭이를 추가로 얻거나 다른 곡괭이를 장착한다. 이전 수리 API는 차감 없이 종료 응답(410)을 반환한다.
- 광물 보관함에서 판매할 종류를 선택하고, 선택한 종류의 보유 수량 전체를 광산 포인트로 바꾼다. 수량 입력과 수량 조절 링크는 제거했다. 선택하지 않은 광물은 보존하며, 광산 포인트는 계정 포인트와 별도로 보관한다.
- 교환소에서 아래 보상을 받는다. 교환 한도는 계정당 종류별로 적용하며, 이전 교환 횟수를 유지한다. 한도가 없는 보상은 반복 교환할 수 있다.

## 운영 데이터와 저장

실행 중의 가격, 수량, 한도, 확률, 활성 여부는 운영 DB `rpgenius_data`의 `PointMine` 레코드에서 읽는다. 보상 아이템 ID는 운영 `Item` 목록에서 이름으로 찾는다. 초기 등록 값은 [point_mine_config.js](../point_mine_config.js)에 있으며 서버 시작이나 import에서 등록·보정하지 않는다.

`node scripts/init_point_mine.js --apply`를 명시적으로 실행해 없던 열쇠를 Item ID **416**에 추가하고, 없던 `PointMine` 설정을 생성했다. 기존 416개 아이템이 동일함을 재조회로 확인했다. 기존 Bundle/Pack/제작식/배너/유저 데이터는 변경하지 않았다. 이후 등록 스크립트를 다시 조회 모드로 실행해 `addKey: false`, `addConfig: false`를 확인했다. 스크립트는 기존 항목을 보존하고 동시 운영 변경 시 조건부 쓰기로 실패한다.

2026-10-11 요청에 따라 `node scripts/update_point_mine_rewards.js --apply`를 명시적으로 실행해 운영 `PointMine.rewards`를 당시 8종으로 변경하고, Item ID 416의 설명에서 하루 한도를 2개로 수정했다. 변경 전 설정은 [백업](../output/point-mine/config-before-reward-change-2026-10-10T22-44-58-575Z.json)에 저장했다. 두 레코드를 조건부 트랜잭션으로 변경하고 재조회해 보상 목록·열쇠 설명 외 운영 설정과 모든 아이템 정의가 동일함을 확인했다. 보상 아이템의 스탯·설명·꾸러미 구성과 유저 데이터는 수정하지 않았다. 기존 `zeta`, `card9`, `job8`, `card8` 보상 ID를 유지해 이전 교환 횟수가 새 한도에 포함된다. 제거한 보상의 교환 기록도 보존한다. 드랍 한도 코드와 UI의 실서비스 반영에는 새 코드 적용이 필요하다.

2026-10-11 추가 요청에 따라 같은 스크립트를 명시적으로 실행해 운영 `PointMine.rewards`만 위 15종으로 변경했다. 변경 전 설정은 `output/point-mine/config-before-reward-change-2026-10-11T04-19-04-239Z.json`에 백업했다. 아이템 목록은 변경하지 않고 조건부 트랜잭션에서 동일함을 확인하며, 적용 후 재조회로 다른 광산 설정과 모든 아이템 정의가 보존됐음을 확인했다. `protection`, `advanced-protection`, `card8` 등 기존 보상 ID를 유지해 과거 교환 횟수도 새 한도에 포함한다. 8성 카드팩을 이미 5회 이상 교환했다면 추가 교환할 수 없다. 제거된 `job8`의 기록과 기존 지급 아이템도 보존한다. 아티팩트 열쇠는 운영 Item ID 411의 기존 이름 `아티팩트 옵션 변경열쇠`로 연결했다. 수리 종료·내구도 합산·판매 UI의 실서비스 반영에는 새 코드 적용이 필요하다.

곡괭이, 광물, 포인트, 교환 기록은 유저의 `pointMine`에 저장한다. 열쇠 차감 또는 보상 지급과 광산 기록은 같은 유저 레코드로 저장한다. 기존 계정 행동 큐와 인벤토리 잠금을 사용하며, 요청 ID와 진행 번호로 중복 요청·다른 창의 오래된 요청을 처리한다. 저장 실패 뒤 같은 요청을 확인할 때 재추첨·재차감·재지급하지 않는다. 저장 확인 중에는 새 변경 행동을 막는다. 기존 서버의 단일 프로세스 운영 구조를 따른다.

2026-10-11 상점 변경 요청에 따라 `node scripts/update_point_mine_shop.js --apply`를 실행했다. 운영 `Shop`에서 일반 상점의 `legacy.7J2867CY.10` 상품의 아이템과 일일 한도만 변경하고, 포인트 상점에 열쇠 상품을 추가했다. `Item`과 `Shop`의 동시 편집을 조건부 트랜잭션으로 확인하며, 변경 전 상점은 로컬 `output/point-mine/shop-before-key-sale-2026-10-10T23-11-05-094Z.json`에 백업했다. 재조회로 다른 상품·가격·아이템 정의가 동일함을 확인했고, 구매 기록과 유저 데이터는 수정하지 않았다. 이 스크립트는 조회 모드가 기본이고, 적용을 반복해도 새 상품을 중복 등록하지 않는다. 상점 조회·구매는 운영 Shop을 다시 읽으므로 설정은 상점을 새로 열면 반영된다.

## 참조와 리소스

[Lukim99/point-mine](https://github.com/Lukim99/point-mine)의 커밋 `63480eaca6e34cb78b2f229dff1846a6d17ae033`에서 배경, 광맥, 곡괭이·광물·상자 시트와 효과음을 가져왔다. 스프라이트 경계, 채굴 동작, 내구도, 광물 해금·가중치와 수리 재료도 참고했다. 상자 확률과 보상 가격은 이 이벤트에 맞게 설정했다. 리소스 출처와 효과음 라이선스는 [자산 README](../public/assets/point-mine/README.md)에 기록했다. 열쇠 그림은 이 저장소의 기존 열쇠 아이콘을 재사용했다.

## 화면 구성

원본 `GameScreen.tsx`, `App.css`, `InventoryControls.css`, `ArcaneWorkshop.css`를 참고해 UI를 다시 구성했다. PC는 나무 패널의 광부 정보, 중앙 채굴장, 돌 패널의 인벤토리를 나란히 표시한다. 상단 메뉴는 채굴장·곡괭이 상자·교환소로 구성하며, 중복된 인벤토리 탭과 왼쪽 상자 열기 버튼을 제거했다. 원본의 얇은 상단 메뉴, 금빛 버튼, 곡괭이·광물 카드, 내구도 막대와 획득 창을 적용했다. 모바일은 인벤토리에 접근할 수 있도록 하단 메뉴에서 채굴장·곡괭이 상자·인벤토리·교환소를 전환한다. 광물 판매 버튼은 보관함의 스크롤 영역 아래에 고정하고, 낮은 화면에서는 상자 영역을 스크롤해 개봉 버튼을 사용할 수 있다.

수리 기능과 판매 수량 입력을 제거하고, 같은 종류의 곡괭이는 내구도를 합산해 표시한다. 보상 가격·수량·한도와 곡괭이 확률은 기존 API 응답을 사용하며, 교환소에 현재 교환 횟수와 최대 한도를 표시한다. 교환 성공 시 하단 완료 문구와 빈 상태 영역은 표시하지 않는다. 오류·결과 재확인 안내는 유지한다. 격리 서버의 Chrome에서 보상 교환 후 하단 메시지가 없고 카드의 완료 버튼이 유지됨을 확인했다.

## 검증

수리 제거·내구도 합산·15종 교환소 변경 후 `node --test tests/point_mine_event.test.js tests/yut_event.test.js tests/songpyeon_item.test.js tests/user_cache.test.js`에서 **17개 통과**를 확인했다. 기존 곡괭이 내구도 합산과 장착 보존, 동일 종류 추가 획득, 소진된 종류의 재획득, 선택 광물 전량 판매, 부분 판매 거절, 수리 API 종료, 보상 가격·수량·한도, 과거 교환 기록 보존, 저장 실패 재시도를 검증했다. 운영 DB 쓰기 없이 AWS 경계를 메모리로 격리했다. 같은 격리 서버의 Chrome에서 내구도 `2 + 4 = 6` 합산, 추가 획득 후 `14`, 채굴 후 `13`, 돌 11개·석탄 3개 전량 판매로 17P 획득과 구리 보존, 아티팩트 열쇠 300P 교환과 새로고침 복원을 확인했다. 수리 버튼과 수량 입력·조절 링크가 없고, 교환 후 하단 완료 안내가 없으며, 브라우저 오류가 없음을 확인했다.

이벤트 최초 구현 시 다음 기존 Node 테스트 도구로 **44개 통과**를 확인했다. DynamoDB/S3 경계를 격리해 운영 DB 쓰기 없이 실행했다.

```powershell
node --test tests/web_game_actions.test.js tests/general_field_parity.test.js tests/butagame_field_drops.test.js tests/point_mine_event.test.js tests/yut_event.test.js tests/songpyeon_item.test.js tests/chuseok_event.test.js tests/user_cache.test.js test/node-kakao-auth.test.js
```

인증, 윷놀이 종료와 기존 기록 보존, 16종 추첨, 동시 요청, 채굴·수리·광물 판매·보상 교환, 수량 검증, 모든 변경 행동의 저장 실패 재시도, 운영 가격·수량 반영, 하루 드랍 한도와 한국 날짜 갱신을 포함한다.

실제 서버 코드와 메모리의 검증 계정으로 Chrome에서 상자 개봉 → 채굴 → 광물 수리 → 선택 판매 → 보상 교환과 새로고침 복원을 확인했다. 저장 실패를 주입한 뒤 UI 재시도로 추가 채굴 없이 저장이 복구되는 것도 확인했다. PC 및 390px·320px 모바일 폭에서 가로 넘침이 없고, 모바일 판매 버튼이 하단 메뉴 위에 표시되는 것을 확인했다. 확률 창에 16종이 표시되고 새 광산 자산이 정상 로드된다.

UI 개편 단계에서 관련 테스트 11개와 같은 격리 서버의 상자 획득 창, 채굴, 곡괭이 장착, 내구도 수리, 수량 지정 판매, 보상 교환과 새로고침 복원을 확인했다. 320px·390px 모바일, 820px 태블릿, 1280px·1920px PC 폭에서 가로 넘침이 없고, 320px 화면에서도 상자 버튼으로 개봉할 수 있음을 확인했다.
