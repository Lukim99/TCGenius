# 1차 유니크 아바타

캐릭터별 아바타 17종. 기본 공격력 +250, HP +2500이며 아래 추가 옵션 중 하나를 사본마다 선택한다. 선택은 무료이고 사냥, 레이드, 대전 중에는 서버가 거부한다. 기본 선택은 최종 피해다.

| 선택 옵션 | 효과 |
| --- | --- |
| 최종 피해 | +3% |
| 치명타 확률 | +3% |
| 회복 및 보호막 효과 | 각각 +5% |
| 받는 피해 감소 | 3% |
| 아이템 드랍율 | +5% |

외형으로 장착한 유니크 아바타는 해당 캐릭터의 궁극기(스펙터가 있으면 스펙터 궁극기)에 전용 컷씬을 표시한다. 능력치만 적용한 경우 외형과 컷씬은 외형 아바타를 따른다. 필드, 훈련장, 월드보스, 파티, 대전, 낙원의 성공한 스킬 사용에 연결한다. 기존 궁극기 재생기의 중복 방지와 종료 처리를 유지하며 일반 컷씬을 대체한다.

## 바인드 큐브

| 큐브 | 가격 | 유니크 확률 |
| --- | --- | --- |
| 바인드 큐브 | 300P | 10% |
| 황금 바인드 큐브 | 300마일리지 | 15% |
| 마스터 바인드 큐브 | 600마일리지 | 25% |

보유 아바타 2개와 큐브 1개를 소모한다. 같은 이름의 사본 두 개도 가능하다. 캐릭터 선택은 재료의 캐릭터와 무관하다. 실패하면 선택한 캐릭터의 일반 등급 아바타 중 하나를 동일한 확률로 받는다. 프레스티지, 한정, 유니크는 실패 결과에 포함하지 않는다.

실패 횟수는 계정 공통이며 큐브 종류·캐릭터를 바꾸어도 유지한다. 14회 실패 다음인 15회째는 100% 유니크다. 유니크 획득 시 0으로 초기화한다. 결과를 서버에서 결정하고 재료·큐브·누적 횟수·결과를 조건부 단일 DB 변경으로 저장한다. 같은 요청의 재전송은 직전 결과를 반환하고 추가 소모하지 않는다.

아바타는 개별 `id`, `name`, `trades`를 가지며 유니크는 `option`도 갖는다. 기존 사본은 접근 시 안정적인 식별자를 얻고, 운영 정의를 시작 시 보정하거나 유저 테이블을 일괄 갱신하지 않는다. 장착한 사본을 재료나 거래로 제거하면 해당 장착을 해제한다. 다른 사본은 보존한다.

유니크의 거래 제한은 최초 획득 이후 최대 3회다. 경매 구매, 구매 주문에 판매, 우편 선물에서 1회씩 차감한다. 경매 등록과 취소는 횟수를 차감하지 않으며 사본 식별자와 옵션을 유지한다. 받는 계정이 같은 아바타를 보유해도 수령할 수 있다.

## 출시 데이터와 자산

`node scripts/register_unique_avatars.js`는 운영 DB에서 신규 항목만 추가하는 계획을 출력한다. `--apply`는 원본 백업 후 Fashion·Item·Shop을 조건부 트랜잭션으로 추가한다. 기존 항목, 인덱스, 운영자가 비운 구성과 가격을 보존하며 재실행은 무변경이다. 서버 시작이나 모듈 import에서는 실행하지 않는다.

`node scripts/migrate_unique_avatar_assets.js --apply`는 요청받은 폴더의 관련 에셋 123개만 `tcgenius/assets/` 아래로 복사한다. 기존 S3 파일이 다른 내용이면 덮어쓰지 않는다. 업로드 후 다시 읽어 SHA-256으로 검증한다. 17명 모두의 카드 레이어 85개는 `cardImage/카드분리/캐릭터`, 전신과 컷씬은 `ui/유니크아바타`, 아이콘은 `itemImage` 아래다. 전투 캐릭터는 투명 카드 레이어를 사용한다.

합성 효과음은 [기존 CC0 외부 음원](../public/assets/potential-forge/CREDITS.md)의 선택·충전·충격·공명·개화·팡파르 샘플을 사용한다. 원본 제작자와 라이선스는 해당 출처 문서에 있다.

합성 화면과 아바타 선택 화면은 Claude CLI의 `claude-opus-5-5`로 디자인했다. `public/unique-avatar-ui.js`와 `public/unique-avatar.css`를 사용하며 실제 서버 응답 이후에만 결과 연출을 시작한다. 인벤토리에서 큐브를 사용하면 해당 큐브를 선택한 상태로 합성창을 연다.

운영 정의를 반영한 뒤에는 변경된 코드의 배포 및 서버 재시작이 필요하다. S3는 기존 시작 동기화로 배포 서버에 복원된다.
